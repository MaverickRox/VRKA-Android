## 3. Implemented Corrections & Architectural Verification

### 3.1 App Language Selector Restoration & Layout Alignment
- **Root Cause of Defect**: When localization changes were ported from the candidate workspace onto the v5.0.2 release-base worktree, `SettingsScreen.kt` was partially reverted to v5.0.2 to strip unreleased F-Droid opt-in switches (`autoCheckAppUpdates`, `autoCheckComponentUpdates`). During that reconciliation, the App Language selector row and its accompanying dialog were inadvertently omitted from `SettingsScreen.kt`. Furthermore, in the initial dialog layout, rows using `Arrangement.SpaceBetween` without weighted text constraints caused long labels (Simplified Chinese, Brazilian Portuguese, European Portuguese) to push trailing radio buttons toward or beyond the right screen margin.
- **Restoration & Alignment**:
  - Located in the **Appearance** section after the Font control (`pref_font`) and before the Components & Updates heading (`settings_heading_components`).
  - Displays the active language name (or `System default` when no language override is active) via `VrkaSettingRow`.
  - Provides a visible `Change` button (`VrkaOutlinedButton`, height 36.dp).
  - Language selection dialog displays:
    1. `System default` in a separate row at the top with a dedicated radio button, separated from the language list by a `VrkaDivider()`.
    2. The 14 application languages listed in exact ascending alphabetical order of their English names:
       1. Arabic (`ar`)
       2. Bengali (`bn`)
       3. Chinese (Simplified) (`zh-CN`)
       4. English (`en`)
       5. French (`fr`)
       6. German (`de`)
       7. Gujarati (`gu`)
       8. Hindi (`hi`)
       9. Kannada (`kn`)
       10. Portuguese (Brazil) (`pt-BR`)
       11. Portuguese (Portugal) (`pt`)
       12. Spanish (`es`)
       13. Tamil (`ta`)
       14. Telugu (`te`)
    3. **Responsive Row Layout**: Uses `Modifier.fillMaxWidth()` on the option row, `.selectable(selected = isSelected, onClick = ..., role = Role.RadioButton)` for cohesive accessibility, `Modifier.weight(1f).widthIn(min = 0.dp).padding(end = 12.dp)` on the text label to ensure natural text wrapping without unbounded measurement, and a fixed `Box(modifier = Modifier.size(24.dp))` trailing container for the radio button. All radio buttons remain stably positioned and completely visible regardless of label length.

### 3.2 Locale Architecture & Persistence
- **Android 13+ (API 33+)**: Uses public Android system API `LocaleManager.setApplicationLocales(LocaleList)`. Synchronizes bidirectionally with Android system per-app language settings in OS Settings.
- **Android 8.0 - 12L (API 26 - 32)**: Uses persistent `SharedPreferences` storage (`vrka_locale_preferences`) and applies configuration context via `LocaleHelper.applyLocale(newBase)` inside `MainActivity.attachBaseContext`.
- **System Default Restoration**: Selecting System default (`code = ""`) clears the SharedPreferences override, resets Android 13+ locales via `LocaleList.getEmptyLocaleList()`, and restores the system default locale.

### 3.3 Video and Audio Selection Localization
- Added `media_type_video` and `media_type_audio` string resources across all 14 locales.
- Updated `HomeScreen.kt` to capture string resources in `@Composable` scope and return localized strings from `VrkaSegmentedControl` label callback.
- Updated `ConfigurationSummary.kt` and `Presentation.kt` to use localized string resources for format summary displays.

### 3.4 German Layout Problems
- Action buttons in Custom Command templates now use `Modifier.horizontalScroll(rememberScrollState())` to prevent long translated button labels (`Vorlage hinzufügen`, `Bearbeiten`, `Löschen`) from truncating on smaller screens.
- Navigation bar slot widths use responsive padding to prevent text clipping.

### 3.5 Arabic RTL Navigation
- Updated indicator pill center computation in `VrkaDesignSystem.kt` to account for RTL layout direction.
- Unit tests in `NavIndicatorGeometryTest.kt` verify indicator coordinate centering across LTR and RTL directions.

### 3.6 Dedicated Regression Test Suite (`AppLanguageSelectorTest.kt`)
Added 8 comprehensive unit tests verifying:
1. `testAll14LanguagesAvailableAndOrderedByEnglishName`: Verifies all 14 languages are present, Portuguese variants are distinct, and order strictly follows English alphabetical sort.
2. `testSystemDefaultIsAvailableAndAtTopOfSupportedLanguages`: Verifies `supportedLanguages` has 15 items with System default at the top (`code == ""`).
3. `testDisplayLabelFormatting`: Verifies `displayLabel` format across English, Arabic, Gujarati, Chinese, and Portuguese variants.
4. `testTagNormalization`: Verifies BCP-47 and Android resource qualifier tag normalization (`pt-rBR` $\rightarrow$ `pt-BR`, `zh-Hans` $\rightarrow$ `zh-CN`, etc.).
5. `testLocalePersistenceAndSystemDefaultClearing`: Verifies persistent storage and clearing of language overrides via mock context and preferences.
6. `testResourceDirectoriesAndLocalesConfigParity`: Verifies presence of all 14 locale directories, strings files, and `locales_config.xml` declarations.
7. `testSettingsScreenContainsLanguageSelectorInAppearanceSection`: Verifies UI ordering: `settings_heading_appearance` $\rightarrow$ `pref_font` $\rightarrow$ `pref_app_language` $\rightarrow$ `settings_heading_components`.
8. `testLongLanguageLabelsLayoutConstraintsAndAlignment`: Verifies that long language labels wrap within weighted text bounds (`weight(1f)`, `widthIn(min = 0.dp)`) without moving or clipping fixed-size radio button containers, and verifies accessibility `.selectable(role = Role.RadioButton)` semantics.
